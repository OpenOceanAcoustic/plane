# 实验室协作增强使用与部署说明

本轮在现有 Plane Community Edition Fork 上增量扩展，复用原账号、项目、任务、Pages、附件、版本和实验室贡献数据。当前内网入口为 `http://192.168.137.90:8080`；管理后台为 `/god-mode/`。功能规格见 [enhancement-spec.md](enhancement-spec.md)，检查和部署状态见 [enhancement-progress.md](enhancement-progress.md)。

## 个人文件夹与任务看板

打开侧栏“个人规划”。默认 A/B/C/D 文件夹以错位页签显示，“未分类”始终保留。使用“新增文件夹”创建更多页签；文件夹菜单支持改名和删除。删除文件夹只取消归类，不删除个人事项或原生项目任务。

拖动页签的排序手柄调整顺序，拖动事项手柄跨文件夹移动。键盘用户先聚焦手柄，按空格拾起、方向键移动、空格确认，Escape 取消。看板操作保存到后端，刷新后仍保留顺序和归类。

“个人事项”适合学习、科研和带教安排；“引用项目任务”选择本人有权限访问的跨项目任务。引用保持原任务身份，任务状态在个人看板、项目看板、任务表格和甘特中同步。负责人通过“项目状态映射”配置待做、进行中、待验收和完成；待验收需要项目内独立的 started 状态。

## 个人日历与团队排期

个人规划的日历提供日、周、月视图，默认周视图。日历采用 `Asia/Shanghai`、周一开周、十五分钟步长。通过“安排时间”、事项上的日历按钮或选择空白时段创建时间块；拖动移动、拉伸调整时长，打开时间块可编辑、拆分或删除。同一事项允许安排多个时间块。

排期只调整计划投入时间，不改变项目任务的起止日期和实际完成记录。时间重叠会提示但允许保存。保存失败时日历回退；遇到其他页面同时修改，界面提示冲突并刷新记录，保留当前表单输入供重新核对。

“团队排期”提供横向人员时间轴和人员分列日历，默认横向周视图，可筛选人员、项目和日期。时间轴空白行与日期表头支持鼠标左键拖动浏览；放大后平移当前日期范围，拖到边界或在总览中拖动时切换相邻时段。每次手势最多切换一次，松开即停止。点击“框选排期”可以在本人行拖选新时间块，再次点击恢复浏览。时间块的点击、本人移动和拉伸继续使用原操作。工作区管理员、项目负责人可查看团队安排；成员维护本人时间块。

私人事项默认对他人仅显示“忙碌”，本人可选择公开。无权访问的项目任务同样仅显示忙碌时间。此规则由后端执行，覆盖接口、提示、图表、下钻和导出；项目筛选不会暴露隐藏任务的项目归属。日历 CSV/JSON 导出与当前可见范围一致。周视图时间块底部的边缘手柄用于调整结束时间；横向时间轴使用右侧边缘手柄，拖动时间块主体则移动整块。

## 任务表格与八类自定义字段

打开“任务表格”，选择项目。“管理字段”由工作区管理员创建或修改字段，项目负责人选择该项目启用哪些字段。支持文本、数字、单选、多选、日期、成员、布尔和 URL；输入值由后端校验。字段停用后历史值保留，已有值的字段不能直接改为另一种类型。

表格支持任务和字段搜索、按列筛选与排序、分组、列显隐、分页及“导出筛选结果”。原生任务详情也显示该项目启用的字段，可在权限允许时直接编辑。停用字段不删除旧值；本轮没有公式字段和跨表关联。

## 项目甘特与日期联动

进入项目任务页面，选择原生“时间线”。增强甘特使用同一批原生任务，保留任务筛选和详情入口；可切换日、周、月、年尺度。未排期任务单独列出，点击“排期”补齐日期。

时间条支持移动和调整时长。“任务依赖”用于维护同项目的前置关系。系统拒绝自身依赖和循环依赖；前置任务结束后，后续任务最早于次日开始，按自然日计算。

日期操作先显示变更预览，再统一确认。联动保留后续任务时长，仅顺延违反依赖的任务。缺少必要日期时先补齐；取消预览不会保存。确认时后端锁定相关记录并核对版本，若任务已变化或涉及无权修改的任务，整次提交取消，需要重新预览。成功后记录原生任务活动和审计。

## 实验记录、任务关联、附件与版本

在项目 Pages 列表使用“新建实验记录”，或在任务详情的实验文档区域创建记录。模板包含目标、方法、配置、结果、结论、后续事项六个章节，创建的是原生 Page，编辑器、附件和版本功能继续沿用 Plane。

任务详情可“关联已有文档”或“解除关联”；Page 编辑页面可关联、查看和打开同项目任务。双向关系由独立关联表保存，不依赖文档正文中的提及日志。解除关联保留文档，重新关联不会复制原 Page。私人文档只对本人可见，退出项目或工作区后不能继续查看文档及历史版本。

项目 Pages 列表和工作项的实验文档区域均提供“上传文档”。选择或拖入 TXT、MD、DOC、DOCX、XLS、XLSX 文件，填写文档名称，可选私人；从工作项上传时自动关联当前工作项。空文件、不支持的格式和超过实例大小限制的文件在选择后立即提示。

TXT、MD 提供“阅读”和“下载”；TXT 按原文显示，MD 由 react-markdown 渲染。Word、Excel 提供原文件下载。原生文档页面也显示文件名称和相同操作。文件保存在既有附件存储，并绑定上传时的文档版本；后续编辑在线正文不会改写原文件。预览支持 UTF-8（含 BOM），其他编码文件仍可下载，需转为 UTF-8 后重新上传才能在线阅读。

文件遵循项目和私人文档权限；跨项目悬赏仅能读取负责人明确共享的文档版本，撤销共享或任务授权后阅读与下载一并失效。附件随数据库和对象存储备份归档。图片仍可通过原生编辑器的图片菜单或 `/image` 插入；文档版本历史和任务双向关联继续沿用 Plane。

## 悬赏流程图与贡献

在“悬赏大厅”的任务卡点击“查看流程图”。图中显示发布、重大发布复核、认领、确认开工、提交、独立验收、重大验收复核，以及通过、部分通过、返工、不通过、冲正和重新验收等节点。当前节点高亮，历史记录可点击查看；只有当前账号允许执行的动作显示操作按钮。

流程图投影现有悬赏记录，不建立另一套状态。认领、批准、确认、开工、提交、验收、复核、取消、冲正和重新验收都调用原业务接口，继续检查阶段 B、团队 T、WIP、独立验收和幂等键。重大任务必须完成独立复核后才进入对应结果和记账。

部分通过填写参与者的累计 VC，再次验收只增加差额；有效探索负结果依原验收条件处理。负责人不自动分成。更正使用追加冲正记录，保留任务和人员快照；“更正后重新验收”回到独立验收，不能跳过复核。账本按项目显示和导出，不产生跨项目成员排名或现金支付。

## 数据总览

“数据总览”提供十二张图表。先选择日期、项目和人员，再按项目、排期、VC 类别查看；有团队查看权限时可切换本人或团队排期。点击图表数据打开源记录下钻。每张图支持 PNG、CSV、JSON，页面还支持批量 CSV/JSON；下钻列表可单独导出。

| 类别 | 图表                    | 统计含义                                     |
| ---- | ----------------------- | -------------------------------------------- |
| 项目 | 状态分布                | 当前可访问任务按原生状态统计                 |
| 项目 | 项目完成率              | 已完成任务数 / 当前任务总数，0% 是有效结果   |
| 项目 | 新增与完成日期趋势      | 按任务创建时间和现有完成时间统计，不补造历史 |
| 项目 | 逾期任务分布            | 到期仍未完成的任务                           |
| 排期 | 成员每周计划时数        | 时间块按上海日期和周一分周，跨周分别统计     |
| 排期 | 每日排期热力图          | 当前可见时间块的每日计划小时                 |
| 排期 | 事项类别占比            | 学习、科研、带教等类别对应计划小时           |
| 排期 | 重叠时间分布            | 同一人的重叠时间单独统计                     |
| VC   | 阶段预算占用            | 当前冻结预算、团队占用和剩余，不模拟历史余额 |
| VC   | 项目内成员计划与实际 VC | 分工计划与净授予贡献，按项目查看             |
| VC   | 授予与冲正趋势          | 真实账本授予和冲正记录                       |
| VC   | 验收结果分布            | 现有验收记录的结果统计                       |

排期是计划投入，不是实际工时，也不默认假设每周四十小时。预算显示当前余额，日期筛选不把它改造成历史预算曲线。空数据提供空状态，不使用示例数字。私人内容和不可访问任务在图表、下钻、导出中执行相同隐私规则；切换筛选时旧范围的结果不会继续导出。

## SSH 邀请与账号恢复

既有邀请和动态码认证保留。服务器终端运行以下命令；脚本在终端输出一次性注册或恢复 URL，不生成注册链接文件。

```bash
sh backend.sh --help
sh backend.sh                               # 仅首次管理员初始化
sh backend.sh invite --workspace openoceanacoustic --role 15
sh backend.sh list
sh backend.sh revoke --id INVITATION_UUID
sh backend.sh reset --username MEMBER_USERNAME
```

邀请角色为访客 5、成员 15、管理员 20；`--workspace` 填目标工作区的 slug，即访问路径中的工作区标识。`revoke` 的 ID 来自创建输出的 `ID:` 或 `list`，不是链接中 `#` 后的 token。默认二十四小时有效，预览不消耗，绑定 Authenticator 成功后失效。已有管理员时使用 `invite`；仍有有效首次初始化邀请时先撤销旧邀请，再重新初始化。`list` 保留邀请状态和 ID，不重新输出已发 token；链接丢失时撤销旧邀请并生成新链接。

`reset` 立即使旧动态码、会话、API 令牌和 Live 连接失效，生成原账号的一次性重新绑定链接；账号、任务和 VC 保留。登录使用用户名和六位动态码，用户名不区分大小写；已使用时间步不能重用。每账号滚动十分钟最多五次提交，成功也计数，换 IP 或重启不重置额度。

## 现有实例升级、启停与备份

在仓库根目录执行。已有实例不需要重新生成配置或重复初始化账号。升级前备份数据库、附件、配置及独立认证密钥；升级备份使用 `--keep-stopped` 保持写入服务停止，直到构建、恢复演练和迁移完成后再启动。首次部署的环境准备见 [部署管理说明](README.md#首次准备)。

工具链固定 Vite 7.3.7，与 React Router 7.17 明示支持的版本范围一致，采用成熟的 Rollup/esbuild 构建流程；web 显式使用 esbuild 压缩，以降低构建阶段随机原生崩溃的风险。按以下安装和串行构建命令执行即可，无需额外设置。该工具链的重新构建与完整 E2E 结果以交付记录为准。

```bash
python3 tools/lab/backup.py backup /ABSOLUTE/NEW/BACKUP_DIR /SEPARATE/KEY_DIR --keep-stopped
pnpm install --frozen-lockfile --network-concurrency 4 --child-concurrency 1
tools/lab/lab.sh build
python3 tools/lab/backup.py restore-verify /ABSOLUTE/NEW/BACKUP_DIR /SEPARATE/KEY_DIR/BACKUP_DIR_NAME.totp.key
docker compose -p ooa-plane-lab -f compose.lab.yml run --rm api python manage.py migrate --noinput
tools/lab/lab.sh start
tools/lab/lab.sh status
```

每一步成功后再执行下一步。备份、构建、恢复演练或迁移失败时先保留停写状态并排查，再决定恢复旧版本或完成升级；不要继续迁移或启动不匹配的构建。普通定期备份省略 `--keep-stopped`，备份完成后自动恢复原来运行的服务：

```bash
python3 tools/lab/backup.py backup /ABSOLUTE/NEW/ROUTINE_BACKUP_DIR /SEPARATE/KEY_DIR
```

恢复演练使用新 API 镜像和独立临时项目，先核对升级前记录数，再运行增量迁移，校验附件和加密凭据。维护容器连接临时数据库及本容器回环地址，不启动正式 Redis、worker 或应用服务；演练结束只清理本次临时卷，不覆盖运行数据。真正灾难恢复须在停机、确认目标卷后恢复 dump、附件、配置和匹配密钥，并清除恢复的旧会话。

日常停止和启动使用 `tools/lab/lab.sh stop`、`tools/lab/lab.sh start`，不会删除数据。认证密钥为 `.secrets/lab-totp.key`，必须单独备份；数据库备份不能替代它。正式项目禁止执行 `down -v`。入口监听地址可以是 `0.0.0.0`，成员访问和邀请链接应使用内网 IP 或域名；团队长期使用时统一配置 HTTPS。

## 隔离的真实浏览器验收

正式实例占用 8080 时，使用独立项目 `ooa-plane-e2e` 和 8081。准备器复制已完成的 web/admin/space/live 构建产物到仓库外目录，只在副本中将配置的公开地址改为 `http://localhost:8081`，生成独立数据库、附件、Live 和 TOTP 密钥配置；不修改正式 `.env`、构建目录或卷。

以下命令需在四个前端和 API 镜像构建完成后运行；要求支持 `!override` 的 Docker Compose v2。每次准备使用新目录，测试栈从空卷开始。

```bash
export LAB_E2E_DIRECTORY=$(python3 tools/lab/e2e/prepare.py)
e2e_compose=(docker compose --env-file "$LAB_E2E_DIRECTORY/root.env" -p ooa-plane-e2e -f compose.lab.yml -f compose.lab-e2e.yml)
"${e2e_compose[@]}" up -d plane-db plane-redis plane-mq plane-minio
"${e2e_compose[@]}" run --rm api python manage.py migrate --noinput
"${e2e_compose[@]}" run --rm api python manage.py register_instance local-lab
"${e2e_compose[@]}" run --rm api python manage.py configure_instance
"${e2e_compose[@]}" run --rm api python manage.py create_bucket
"${e2e_compose[@]}" run --rm api python manage.py collectstatic --noinput
"${e2e_compose[@]}" up -d --no-build
LAB_E2E_PROJECT=ooa-plane-e2e LAB_E2E_BASE_URL=http://localhost:8081 pnpm exec playwright test --config tools/lab/e2e/playwright.config.ts
"${e2e_compose[@]}" down -v    # 仅清理明确指定的隔离测试项目
```

测试端口为入口 8081、API 8011、附件 9110、附件控制台 9191，均绑定回环；数据库、Valkey 和 RabbitMQ 不暴露端口。浏览器脚本只允许指定的测试项目，使用临时管理员与夹具，不改动当前成员账号。脚本用于验证动态码登录、原生项目封面上传、任务、文件夹、日历、字段、甘特、实验记录和流程图、图表与导出，实际通过情况以交付记录为准。

此隔离栈必须始终带 `compose.lab-e2e.yml` 和私有 `--env-file` 启动；不要用 `LAB_COMPOSE_PROJECT=ooa-plane-e2e tools/lab/lab.sh init/start`，也不要在共享工作区执行 `setup --public-url http://localhost:8081`，这些路径会采用正式端口或改写正式配置。重建前端后重新准备副本；只改 Compose 端口不足以改掉已编译的 Live/公开地址。
