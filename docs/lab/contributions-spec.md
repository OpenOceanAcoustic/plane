# 我的项目与 VC：确认方案

实施基线：`c3c8d035e712ff7515e613aded5d857943c844f0`（`ooa/main`）。本次以功能代码、使用说明和 PR 为交付点。

## 页面

新增工作区侧栏“我的项目与 VC”（`/{workspace}/lab/contributions`），固定展示当前工作区、当前登录用户的信息。

- 顶部展示全时期个人净 VC、累计获得、累计冲正；净额为全部本人 Ledger.delta 的和，筛选项目和月份不改变顶部总额。
- 项目集合合并当前有效项目成员资格、本人已批准且已确认的悬赏分工、本人历史 VC，按项目 UUID 去重；尚无贡献的参与项目显示 `0.00`。
- 历史个人金额、入账时间、项目和任务快照在退出项目、撤销授权、删除源任务后继续保留。只恢复有留存证据的参与关系。
- 只读月历默认上海当前月，支持上一月、下一月、选择月份、本月及项目筛选。按日期和项目汇总，分别显示获得与冲正；同日净零仍显示两种变化。
- 点击日期或项目日汇总加载逐笔明细，包括入账时间、项目、任务、VC 增减和类型；明细分页，每页 50 条。
- 获得日期采用 Ledger.created_at，按 Asia/Shanghai 划日；冲正显示在冲正自身入账日，不改变原获得日。“有效探索负结果”验收不等于负 VC。
- 计划配额、预计奖励、人民币支付不计入个人 VC。配色采用稳定项目色和 Plane 主题变量；项目名称和正负金额始终可辨识。窄屏纵向布局。
- 不展示政策、流程、权限或实现细节的说明性小字；仅保留字段、状态、结果、操作及必要错误。

## 接口与权限

所有接口位于 `/api/workspaces/{slug}/lab/`，只读，固定查询本人，不支持指定其他用户。

| 接口                                                                               | 返回                                                                                                                       |
| ---------------------------------------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------- |
| `GET me/contributions/`                                                            | timezone、totals（earned/reversed/net）、projects（项目 ID/名称、本人三个金额、参与来源、历史状态、当前项目访问能力）      |
| `GET me/contributions/calendar/?month=YYYY-MM&project_id=可选`                     | timezone、month、该月筛选 totals、按 day/project 分组的金额与笔数                                                          |
| `GET me/contributions/entries/?month=YYYY-MM&day=可选&project_id=可选&cursor=可选` | timezone、results、next_cursor；每条仅本人入账时间、日期、项目/任务快照、delta、award/reversal、冲正引用和当前详情访问能力 |

月份默认上海当前月；选日限定于所选月份。流水按 created_at 和 UUID 倒序，使用稳定游标分页。所有 VC 金额由服务端 Decimal 聚合并返回两位小数字符串；前端不使用浮点数重新汇总。

个人账目归属以不可变参与者 UUID 和工作区快照为依据，不依赖当前项目资格。旧缺失字段只能利用有证据的不可变关联识别归属，不能按姓名猜测。

历史摘要不返回执行资料、附件、证据或内部验收全文。有当前原生项目/任务读权限时，可打开已有工作项右侧总览；只有悬赏任务授权时，可打开已有受控悬赏详情；撤权或源任务删除后只展示个人历史快照。公开浏览摘要不等于任务执行授权。原接口继续执行原有 ACL。

使用现有 Ledger、Stage 项目快照及 Allocation，无业务数据迁移。状态层必须防止旧月份、项目、日期及分页请求的迟到响应覆盖当前筛选；失败显示错误，并允许刷新重试。

## 验收与交付

- PostgreSQL 契约覆盖本人/工作区隔离、项目去重、零 VC、正式成员及跨项目确认、历史保留与源接口仍拒绝越权。
- 验证多项目累计、部分验收、多笔入账、跨月冲正、午夜日期边界、两位精度、同日净零、负结果验收和稳定分页。
- 浏览器覆盖页面总额、月历及明细、项目/日期联动、迟到请求、刷新、分页、详情权限、窄屏、空状态和失败重试。
- 完成后端、浏览器、类型、Lint 和生产构建验证，提交前分别审查规范与方案符合性。
- 独立功能分支提交 PR 到 `ooa/main`，保留已有未提交改动；本次不包含直接合并或正式服务发布。
