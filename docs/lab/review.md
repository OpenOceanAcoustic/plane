## Spec

- **P1：悬赏查询锁不可空关联。** 规格要求发布、认领、验收可运行，但可空关联查询会被 PostgreSQL 拒绝。已修复；真实 PostgreSQL 的发布、重大验收与并发预算测试已进入 CI。
- **P1：恢复账号后已有 Live 连接仍可收取文档更新。** 规格要求立即吊销旧会话。已增加按用户的 Redis 撤销通知和连接关闭，以及每次编辑前的持久会话复验；两项 Live 契约测试通过。
- **P2：开发 StrictMode 清掉邀请 fragment。** 规格要求本机开发可注册。已改为 ref 控制只捕获一次；真实 Chromium 在 StrictMode 的注册绑定测试通过。

未发现实质性额外范围。首轮共 4 项规范发现和 3 项规格发现；规范轴最严重的是共享组件位置，规格轴最严重的是悬赏行锁与 Live 会话吊销，均已处理。该评审不代替运行验收；后续回归结果记录在 [progress.md](progress.md)。

## 并发与恢复复查

- WIP 例外过期后全工作区校验会阻止无关编辑和逐项收尾：改为每事务基线身份子集检查，增加真实数据库契约。
- 原生更新先锁任务行、悬赏动作先锁 WIP 会造成反序：改为 BEFORE STATEMENT 统一锁，悬赏操作与原生序号生成按相同顺序进入；最终约束在提交时校验。
- 已关闭分工会让已完成任务重新进入进行中时漏计 WIP：仅在活跃悬赏期间排除已关闭分工，补重新开工测试。
- 不通过的悬赏无法退出 WIP：结案、释放未授予预算、保留历史贡献并将原任务退回待做；补幂等与后续任务测试。
- SSH 重置与重绑确认锁顺序不同：加入按用户的重绑事务锁，补并发确认测试。
- Docker run 的 env-file 保留 Compose 配置引号：恢复前生成临时无引号环境文件，固定隔离项目名，并保护停止过程的 finally 恢复。

以上修复已通过后续 PostgreSQL 契约与完整部署验收，运行证据见 [progress.md](progress.md)。
