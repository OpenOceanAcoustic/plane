# 首轮双轴评审

评审范围 `v1.4.2...c0dcb8e`，依据 [spec.md](spec.md)、根 AGENTS.md 和后端测试指南。规范与规格由两个独立评审分别完成；后续修复在功能分支中。

## Standards

- **明确规范问题：共享表单位置。** 原 `apps/web/core/components/lab/form.tsx` 的通用弹窗和字段没有放入共享 UI。已移至 `packages/ui/src/lab-form.tsx`，补充 Storybook。
- **明确规范问题：测试分类。** 认证 HTTP 测试被标成 unit。已改为 contract，并将该模块测试移至 `plane/tests/contract/api/lab`。
- **判断性建议：Duplicated Code。** 两种导出重复了 CSV 公式处理。已抽取 `plane/lab/export.py` 的共享函数。
- **判断性建议：Primitive Obsession。** 悬赏状态和验收结果使用宽泛 string。已增加有限字面量类型。

另发现两项具体正确性问题：可空关联的 FOR UPDATE 导致 PostgreSQL 报错，以及错误分工 ID 导致 500。前者已限定锁定 self 行，后者改为受控 400/404 并补接口测试。

## Spec

- **P1：悬赏查询锁不可空关联。** 规格要求发布、认领、验收可运行，但可空关联查询会被 PostgreSQL 拒绝。已修复；真实 PostgreSQL 的发布、重大验收与并发预算测试已进入 CI。
- **P1：恢复账号后已有 Live 连接仍可收取文档更新。** 规格要求立即吊销旧会话。已增加按用户的 Redis 撤销通知和连接关闭，以及每次编辑前的持久会话复验；两项 Live 契约测试通过。
- **P2：开发 StrictMode 清掉邀请 fragment。** 规格要求本机开发可注册。已改为 ref 控制只捕获一次；真实 Chromium 在 StrictMode 的注册绑定测试通过。

未发现实质性额外范围。首轮共 4 项规范发现和 3 项规格发现；规范轴最严重的是共享组件位置，规格轴最严重的是悬赏行锁与 Live 会话吊销，均已处理。该评审不代替运行验收；后续回归结果记录在 [progress.md](progress.md)。

## 并发与恢复复查

- WIP 例外过期后全工作区校验会阻止无关编辑和逐项收尾：改为每事务基线身份子集检查，增加真实数据库契约。
- 原生更新先锁任务行、悬赏动作先锁 WIP 会造成反序：改为 BEFORE STATEMENT 统一锁，悬赏操作与原生序号生成按相同顺序进入；最终约束在提交时校验。
- 已关闭分工会让已完成任务重新进入进行中时漏计 WIP：仅在活跃悬赏期间排除已关闭分工，补重新开工测试。
- 不通过的悬赏无法退出 WIP：结案、释放未授予预算、保留历史贡献并将原任务退回待做；补幂等与后续任务测试。
- SSH 重置与重绑确认锁顺序不同：加入按用户的重绑事务锁，补并发确认测试。
- Docker run 的 env-file 保留 Compose 配置引号：恢复前生成临时无引号环境文件，固定隔离项目名，并保护停止过程的 finally 恢复。

以上修复仍需下一轮 PostgreSQL 与完整部署验收。

复查 Standards 未发现新的阻断问题；补充清理项已将附件卷、临时环境文件和恢复 Compose 文件纳入 finally。Spec 发现满 WIP 时自动重开会阻止财务冲正：已将追加冲正与重新验收分离，负责人显式重开时才检查 WIP，并增加满额冲正、重开受限与复验差额契约。

再复查发现归档/软删除任务仍保留 FK；重新验收现在先验证原任务编辑权限，历史冲正仍可进行。已补两种隐藏任务的契约。另补原生状态及状态组不能跳过团队开工确认的数据库保护。

认证终检改为按用户 UUID 保存登录配额，并关闭网页 POST 创建实例管理员；清理过期限流记录时保留账号身份行，避免并发清理连带删除刚提交的登录记录。

部署终检按 Space 原有 SSR 模式增加独立 Node 服务，8080 保留 /spaces/ 前缀代理；Live 和 Space 仅挂载应用、packages、node_modules，不能读取 .secrets 或后台配置。
