# Finance API contract

Base `/api/workspaces/{slug}/lab/`. All money, VC, shares and formula inputs/outputs are decimal strings. No contract/funding-total field exists.

- `GET finance/overview/?project_id=UUID` returns `{manager_id,is_manager,projects:[{id,name,is_lead}],members:[{id,name}],accounts,stages,formulas,forecasts,batches,settlements,commitments,payments,operations,entries}`. Project leads see project funds; members see own forecasts/settlements/commitments/payments, but not project accounts/entries or other members. Public pool manager sees public accounts/entries and project account aggregate only when lead.
- `GET finance/entries/?project_id=UUID&format=csv` exports visible append-only entries (JSON by default).
- `GET/POST finance/formulas/<uuid:project_id>/`: GET `{templates:[{name,task_expression,member_expression}],versions:[{id,project_id,version,task_expression,member_expression,parameters,reason,actor,created_at}]}`; POST `{task_expression,member_expression,parameters:[{name,scope:'task'|'member'|'stage',unit,source,default?:decimal}],reason}` returns formula row. Defaults: task `E * 0.2 * VC / B`; member `E * (0.5 * b + 0.3 * r + 0.2 * VC / B)`.
- `POST finance/preview/<uuid:project_id>/`: `{task_expression,member_expression,parameters:[...],inputs:{E,B,VC,b,r,...},kind:'task'|'member'}` -> `{result,inputs}`; does not save or authorize payment.
- `POST finance/forecast/`: `{stage_id,kind:'task'|'member',basis:'budget'|'received',bounty_id? (task required),user_id? (member required),parameters:{customName:decimal}}` -> forecast row `{id,stage_id,kind,basis,bounty_id,user_id,formula_id,formula_version,expression,inputs,result,created_at}`. E/B/VC/b/r come from authoritative records. Only project leads save task forecasts; these are the published card references. Members can save their own member forecasts. Task uses planned budget VC for budget basis and awarded VC for received basis. Member uses frozen planned_vc for budget and own awarded VC for received.
- `POST finance/<action>/`: every action includes UUID `request_key` (idempotent), `reason` (nonblank), optional `evidence` string (receipt/payment should include proof reference), optional ISO `occurred_at` (fact date, never replaces recorded created_at). Response `{ok:true,id,operation_id}`. Validation errors return HTTP 400 with a DRF message array (or a field `error` for malformed model IDs); permission errors return HTTP 403 with `detail`.

Actions/payloads:

- `manager`: `{user_id}`; only current designated manager, or earliest active workspace administrator for initial designation. Before the first finance mutation, overview reports that candidate without creating policy records; the first authorized mutation persists the designation. Manager must be active administrator.
- `stage`: `{stage_id,E,purposes:[{name,amount}],members:[{user_id,b,r,planned_vc}],upgraded:boolean,history:[{user_id,vc,funding_source,qualified_at:'YYYY-MM-DD',basis,share?}]}`. One frozen plan per existing stage B; purposes sum E, b/r sum <=1, historical shares are frozen by source VC ratio. Historical qualification requires evidence; each funded amount is eligible only from qualified_at through 36 calendar months later, and only within its original or explicitly inherited funding source. Creates project/stage accounts. No default evenly distributed shares.
- `receipt`: `{stage_id,gross,costs,D,source,evidence}`. Actual receipt gross, cost deduction paid once, D <= gross-costs. D partitions future15%,public10%,risk5%,member70%; upgraded member splits history10%/execution90%. Remaining cash stays project. Each receipt batch freezes original historical eligibility.
- `opening`: `{project_id? (omit for public),stage_id?,kind,amount,source,evidence}` imports evidenced opening balance; risk/history imports create an original opening batch (D=0, no repeated split) so subsequent batch risk-use/release and frozen historical qualification remain traceable; execution/history require stage, historical requires upgraded qualification. Public accounts only designated manager; project accounts only project lead.
- `transfer`: `{from_account_id,to_account_id,amount}`; source and destination must both be manageable by actor; prevents unfunded stage allocation. Stage reward accounts cannot be arbitrary transfer source/destination; use receipt, risk-release, carryover/dispute actions.
- `expense`: `{account_id,amount,purpose,user_id?,evidence}`; eligible project/retained/public/research/exploration funds only, rewards use settlements/payments.
- `settlement`: `{stage_id,user_id,amount,performance_basis,forecast_id?}` records member cumulative execution final amount (new immutable revision), total final <= funded stage execution allowance; cannot reduce below paid plus remaining commitments.
- `history-settlement`: `{stage_id}` freezes accrued historical amount by original qualification snapshots, subtracting existing cumulative awards; no generic execution formula.
- `commit`: `{settlement_id,amount}` reserves payment portion against funded available cash and settlement unpaid/uncommitted balance; cannot reserve twice.
- `cancel-commit`: `{commitment_id}` releases unpaid remaining reservation.
- `payment`: `{commitment_id,gross,withheld,evidence,reference}` net=gross-withheld; records offline net outflow and withholding payable separately, consumes gross reservation. Withheld tax stays in withholding account until tax-remit.
- `tax-remit`: `{account_id,amount,evidence}` records offline tax outflow.
- `risk-release`: `{batch_id,amount,evidence}` original risk account -> original stage execution/history in original 90/10 split; no repeated 15/10/5 extraction (future/public/risk). Cannot exceed batch unreleased risk. Must confirm additional execution award separately.
- `future-plan`: `{year,amount}` designated manager moves uncommitted future_pool balance 70% research /30% exploration (annual amount must equal that year's new receipts not previously compiled).
- `dispute`: `{from_account_id,amount}` project lead reserves unsettled stage execution funds into stage dispute account; settlement budget reduced accordingly. `resolve-dispute`: `{from_account_id,to_account_id,amount}` sends dispute to original execution account only.
- `carryover`: `{from_account_id,amount}` unused execution -> retained account, without moving settlement/commitment obligations.
- `stage-allocation`: `{from_account_id,stage_id,amount}` project lead explicitly moves available retained balance to a different frozen stage execution account in the same project. Source must be retained, target must be another frozen stage; cross-project/account spoofing is rejected. No repeated D extraction; new stage final awards require separate confirmation.
- `reverse`: `{operation_id,evidence}` adds compensating entries. Rejects consumed funds, consequential settlement/commitments, and already reversed original records; does not edit historical ledger.

Overview row fields:

- account `{id,project_id,stage_id,kind,label,balance,committed,available,can_manage}`.
- stage `{id,stage_id,project_id,name,B,E,purposes,members,upgraded,history,execution_funded,history_funded,formula_version,can_manage}`.
- settlement `{id,stage_id,user_id,user_name,kind:'execution'|'history',revision,amount,forecast_id,forecast_amount,difference,performance_basis,paid,withheld,net_paid,outstanding,committed,can_manage}` only latest cumulative revision.
- commitment `{id,settlement_id,account_id,user_id,amount,paid,remaining,cancelled,can_manage}`.
- payment `{id,commitment_id,settlement_id,user_id,gross,withheld,net,evidence,reference,created_at,occurred_at,reversed}`.
- batch `{id,stage_id,project_id,gross,costs,D,source,risk,execution,history,risk_released,risk_remaining,history_snapshot,created_at,can_manage}`.
- entry `{id,operation_id,account_id,project_id,stage_id,kind,delta,reason,evidence,actor,created_at,occurred_at,reverses_id}`.
- operation `{id,kind,actor,reason,evidence,payload,created_at,occurred_at,reverses_id,reversed,can_manage}`.

`GET finance/workflow/?project_id=UUID` (alias `finance/flow/`) and `GET projects/<uuid:project_id>/workflow/` use the shared contract `{scope,project_id,title,active_node_ids,nodes,edges,history,actions}`. Nodes are `{id,label,x,y,state:'completed'|'current'|'upcoming'}`, edges `{id,source,target}`, history `{id,label,node_id,actor,created_at,reason,source:{path,label}|null,occurred_at?,evidence?,snapshot?}`, and actions `{id,action,label,node_id,body,enabled,reason}`. Stages and receipt batches are parallel branches; project archive and financial settlement are independent statuses. All projection GETs are read-only. Source history preserves formula/parameter snapshots and fact dates. Enabled actions invoke the same permission-checked services as normal finance forms.

Money/VC calculations always use Decimal through card projections and serialize decimal strings. Percent splits round down separately to cents; remainder stays in its source account (project, risk or future pool). No tail is silently assigned to a member. Future fiscal years and historical qualification dates use the workspace timezone (Asia/Shanghai by default). Formula AST arithmetic supports bounded four operations, parentheses and min/max only; no code evaluation.

Additional public/risk actions and fields:

- `risk-use`: `{batch_id,amount,category:'refund'|'rework',purpose,evidence}` records approved offline responsibility expense against that original batch's actual risk reserve, with provenance. Batch adds `risk_used`; `risk_released` excludes used reserves.
- `exploration-allocation`: `{stage_id,amount}` designated manager moves future_exploration to a frozen stage execution allowance, without redistributing D. Overview `funding_targets:[{stage_id,project_id,project,name,E}]` supplies manager-approved stage references.
- `public-duty`: `{user_id,period:'YYYY-MM',duty,amount,award_id?}` designated manager approves a fixed monthly duty amount. Optional latest award_id appends cumulative revision for that same member/month. Revision may reduce to zero only when paid and outstanding commitments are zero; the original award remains unchanged. No VC formula/ranking applies. Cannot reduce below paid + existing commitments or exceed available public pool funding.
- `public-commit`: `{award_id,amount}` reserves monthly public-duty award payment. `public-cancel-commit`: `{commitment_id}` releases unpaid reservation. `public-payment`: `{commitment_id,gross,withheld,evidence,reference}` records offline partial payment (same gross/net/withholding accounting as project rewards).
- `tax-remit` also accepts the stage-less public withholding account.
- Overview adds `public_awards:[{id,group_key,revision,user_id,user_name,period,duty,amount,paid,outstanding,committed,withheld,net_paid,can_manage}]`, `public_commitments:[{id,award_id,user_id,user_name,account_id,amount,paid,remaining,cancelled,can_manage}]`, `public_payments:[{id,commitment_id,award_id,user_id,gross,withheld,net,evidence,reference,created_at,occurred_at,reversed}]`. Nonmanager users receive only their own rows.
- `members` adds `is_admin`; only those members are eligible for manager designation.
- Stage `history` entries require `{user_id,vc,funding_source,qualified_at:'YYYY-MM-DD',basis,share?}`. share is calculated from frozen valid VC / source total VC; supplied share must agree. `qualified_at` starts the 36-calendar-month eligibility window. Each receipt qualification is checked against its own occurred_at within that window; expired portions stay unallocated, never renormalized among others. Same source retains initial snapshot denominator. Distinct later source has no automatic historical right: matching explicit history must supply `inherited_from` (initial source) and `source_basis` as evidence of authorized inheritance.
- Bounty card projection uses `{stage_budget:B,reward_estimate:{amount,formula_version,error?},received_estimate:{amount,formula_version,error?}|null}`. Public summary gets numeric budget reward/version only; received projection is restricted to leads and confirmed participants. Formula inputs, full E and cash ledgers are not included in the public bounty projection.
