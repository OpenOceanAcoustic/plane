## 修正要求

- Home 的记录态使用紧凑内容卡，不为合法无标题记录生成“—”，不把 JSON 富文本对象强制转为 HTML 字符串。
- 编辑、删除采用小操作入口和明确的删除确认，避免两颗通用大按钮挤占卡片。已有记录不沿用空态的固定 360px 最小留白。
- `native-stickies` 对应独立真实页面：搜索、颜色筛选、记录日期、更多记录、创建与编辑；不能继续仅映射到 Home 并声称覆盖。
- 使用真实 `background_color` 色键；V4 最终记录卡为白色 surface，并未接入规格中的整卡 tone。保留白底，颜色以小色标和原色选项体现，不据此另造整套皮肤。
- 标题不强制必填；保存只使用符合合同的 name、description_html、background_color。修改标题和颜色不得损失原有 HTML 内容或附件。
- 搜索必须说明和落实实际覆盖范围；真实后端只搜索正文，不能把已加载一页的本地筛选称作全量标题搜索。
- 保留真实 API、用户权限、会话、系统返回和用户业务数据。手机管理员入口与导出限制继续生效。
- 独立便签页使用 V4 底部文字“新建便签”按钮；首页保留原加号。导航离开协议放在移动导航模块，不由便签模块承担整个 App 导航。

## 实机追加发现：个人日历·日

原始截图 `native-before/more-lower-primary.png` 实际是个人日历·日，文件名来自导航尝试，不是页面身份；另有对应 UIAutomator 文本。其五日选择条仅有 `active` 类，缺少已有 `lab-chip` 控件样式。正文末尾“安排时间”“今天”偏离 V4：应分别为浮动加号与内容前的小操作。正文多出的日期字段占用短屏空间；已有筛选面板的跳转日期保留。日期图标与日期被通用 `space-between` 拉开，应采用专用 agenda 日期标题；时间列和左边框按原设计对齐。

这些偏差已与未修改的原设计 `plan-day` 和真实源码核对，详情见审计目录 `calendar-day-design-audit.md`。末尾裁切不等于按钮永久不可达，五日条横向滚动是原设计行为，真实日期和记录不改。

升级后的周历截图确认 650px 最小宽度在 360dp 设备只能同时看到前三日及第四日一部分。但原 V4 最终覆盖规则（index.html 第 489–490 行）本身保留 650px 最小宽度和 44px 时间列；35px 屏宽均分是被覆盖的早期规则。临时七列适配已撤回，最终包继续沿用 V4 周历几何及横向滚动。时间文本禁止换行，长时间块标题从顶部显示；这些文字修正保留真实时段、排期与点击处理，不被写成完整周/月视图验收通过。过程截图与临时包保留，不冒充最终布局。

源码另外有三处只使用 `color-mix()` 的背景：日程卡、错误提示、热力图。当前 WebView 为 110，Chrome 官方记录支持从 111 开始，这是版本依据、不是设备执行的功能探测。为前两处添加普通背景并把混色放入 `@supports`；热力图改为主题底色与按真实强度透明度叠加的色层，避免丢失颜色强度。兼容背景兜底不宣称逐像素一致。
