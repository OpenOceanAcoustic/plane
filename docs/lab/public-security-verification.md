## 构建与运行环境

- 前端 15 个类型检查任务、16 个应用构建任务通过；包含 web、admin、space 和 Live 转换 worker。
- 修改文件的 Ruff / 严格 Oxlint / oxfmt 与 `git diff --check` 通过；严格检查没有 warning。构建保留已有 sourcemap 和模块类型提示。
- 使用独立公网配置执行 Django `check --deploy`，只有初期故意不启用 HSTS includeSubDomains / preload 对应的 W005 / W021 提醒。
- API 生产 Dockerfile 完整依赖锁安装及非 root、只读、无网络启动验证通过：合法 Host 返回 HTTPS 301；不可信来源伪造 HTTPS 转发头仍为 301；其他 Host 返回 400。由于本机 Docker registry 对默认 Python 3.12.10 元数据握手失败，本地验证显式使用缓存的 Python 3.12.5 基础镜像，不能代替默认基础镜像验收。
- Node 22.22.1 与 Caddy 2.10.2 使用 Dockerfile 的固定版本及完整 frozen lock 安装。Docker frontend 元数据网络握手同样失败，因此本地采用去掉首行 frontend 指令的同内容 Dockerfile，由 daemon 内置 frontend 构建；没有跳过依赖安装或应用构建。构建阶段限制 `GOMAXPROCS=2` 后通过。
- Live 镜像以 UID 1000、只读根文件系统、无宿主端口启动；健康检查 200、匿名转换 401、非法 WebSocket Origin 403。
- Space 镜像以 UID 1000、只读根文件系统、无网络及宿主端口启动；`GET /spaces/` 返回 200，包含 React Router SSR 外壳。
- 代理镜像以 UID 10001、只读、无网络及宿主端口、`cap-drop ALL` / `no-new-privileges` 启动，在 Compose 相同的 `ip_unprivileged_port_start=0` 下实际绑定容器内 80；合成 HTTP 配置的主站与后台均返回 200，正式 Caddyfile adapt / validate 及日志字段删除断言通过。实际启动先复现基础镜像文件 `cap_net_bind_service` 导致 exec 255，再通过构建阶段移除该文件权限修复；新增回归测试先红后绿，没有扩大运行时权限。这项验证未签发正式域名证书。

PR CI 已加入完整 Live、浏览器安全组件、真实数据库迁移合同、默认 Python 基础镜像的生产启动检查及公网代理镜像完整构建/启动回归。配置存在不等于检查已通过；CI 结果以 PR checks 为准。
