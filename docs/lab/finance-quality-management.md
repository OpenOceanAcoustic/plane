## 项目与质量

工作区侧栏“项目与质量”选择项目。项目成员可编制计划、登记资料、关联已有共享文档或上传文件。资料可按模板直接编写，保存为原生项目文档；同类资料允许多份。成员分工逐项填写成员、工作内容、开始和结束日期，不会覆盖个人日历的实际时间安排。

资料保存为草稿，提交评审后由当前项目管理员、负责人、创建者或有项目成员资格的工作区管理员评审，通过或退回须填写意见。编辑已经通过的资料会形成新版本并重新作为草稿；原评审保留。提交冻结具体文档版本及内容指纹，即使原生编辑器尚未产生新历史版本，内容更新也会使旧结论显示“文档已更新或不可用，待复审”。重新提交会冻结当前内容版本，不自动继承旧通过结论。

质量资料一旦在原生文档编辑器中编辑，后续正文修改继续使用原生编辑器，再从“关联项目文档”重新关联当前文档，避免旧模板正文覆盖协作编辑内容。上传资料同样通过文档版本更新后重新关联。项目计划的原生正文已被编辑时，再编制结构化计划会创建新的计划文档，保留原协作文档。

质量目录只接收本项目共享、未归档文档，不能关联私密或其他项目文档；文档与下载继续使用原访问控制。被质量记录引用的文档版本禁止硬删除，避免历史评审失去来源。归档项目保留质量记录查看，停止修改。质量资料目录提供 JSON 导出，每条记录可查看历史版本。

财务记录、审批与质量评审不自动代办任务验收，也不修改原工作项状态、悬赏贡献或奖励核准。

## 接口与部署

接口前缀 `/api/workspaces/<slug>/lab/`：

- `projects/<project_id>/finance-management/`：GET 当前可见财务来源及汇总，POST 财务动作；`?record_id=<id>` 读取历史，`?format=csv` 导出。
- `projects/<project_id>/quality/`：GET 质量目录及计划，POST 保存、提交、撤回或评审；`?record_id=<id>` 读取历史，`?format=json` 导出。

POST 统一包含 `kind / action / record_id / expected_version / request_key / reason / data`。记录 ID 稳定，版本从 1 递增；重复请求返回原结果，旧版本或复用请求键修改内容返回409。费用、工资、支付、审计和追回均在工作区财务锁下办理；质量在项目锁下办理。迁移 `0025_projectmanagementrecord` 创建来源历史表和不可覆盖／删除保护，不回填或改动已有财务数据。

后端测试需启用 `pytest --migrations --reuse-db`，确保已有 PostgreSQL 业务锁函数及历史触发器实际安装。默认 `--nomigrations` 不足以验证这些约束。
