## 审计发现与优先级

1. **P1：财务权限泄漏**。AI 的 `get_finance_summary` 直接读取账户余额；批注草稿可回显无查看权限的他人工资记录。
2. **P1：VC 与现金混用**。新团队奖金捷径直接把 `Allocation.planned` 当人民币支出，不要求验收或人民币奖励核准。
3. **P1：审批与付款确认不一致**。审批确认使用执行时最新版本，不能发现草稿之后的修改；多笔付款缺少整体事务；聊天确认与按钮确认锁策略不一致。
4. **P2：上下文断裂**。历史 JSON 截前 4,000 字、上下文截前 12,000 字，可能同时丢失最新回复、待澄清字段和 JSON 结构。
5. **P2：项目与会话错位**。口头切换项目后前端未同步；快捷工具首轮没有会话，卡片不持久化；异步历史加载可能覆盖新消息。
6. **P2：草稿身份不稳定**。工时按日期、工资按成员记录已提交状态；同日多条草稿互相影响，刷新后重复提交。
7. **P2：待办/验收角色错误**。付款待办被审批权限前置屏蔽，已批准报销付款缺席，关闭项目仍提示不可执行财务动作；先截历史再筛待办导致旧未办记录消失；团队验收未复用指定验收人规则。
8. **P2：邀请路径错误**。生成路径与真实 `/lab/register/` 路由不一致。
9. **P2：付款冲正脱节**。通用冲正缺少现金悬赏/团队奖金付款关联保护，账务与业务状态可能不一致。
10. **P1：私有报价泄漏**。AI 的工具读取和聊天事实两条路径没有复用原生报价可见范围，普通成员可能读取他人私有报价。
11. **P2：切项目的并发竞态**。模型返回较慢时可能把旧项目答案写到已切换的会话；切回原项目也不能仅比较项目 ID。快捷工具的晚到卡片同样需要绑定发起项目。
12. **P2：付款预览与实付不一致**。报销审计核减不会改变成本本身的版本；原 AI 草稿显示原始金额，确认时可能支付另一个金额。
13. **P2：并发评审覆盖**。同时提交提案评审会丢失另一人的意见，同一人也可能并发确认两个角色。
14. **P2：工时改口误填**。待补工作内容期间，用户回复“昨天”“3小时”“时薪80元”会被当成工作描述；取消和独立查询也可能误续旧事项。
15. **P1/P2：取消与改选动作边界**。取消与执行并发可覆盖已执行状态；跨会话旧引用可取消另一个动作；撤销财务授权后仍可改选并读取他人的成本记录。

结论：已有 DeepSeek 优化接入了很多入口，但主要缺口不只是模型容量。上下文需要保留当前事项、明确项目边界；AI 读取需要沿用业务权限；写入需要统一版本、幂等和事务控制。这三层比继续增加提示词和入口更优先。

## 验证方式

复用本机测试镜像，在独立 internal Docker 网络中运行新 PostgreSQL/Redis/MinIO；不接生产数据库、不运行现有面向生产的 `.lab-ci/run.sh`，不携带生产密钥。使用真实 PostgreSQL migrations，以验证并发锁、账务触发器和不可覆盖历史。复用现有 `laboratory` 负责人、成员、验收人、独立成员角色，并单独授予审批/付款权限。没有登录线上 Harness 账号写入演示账目。

真实模型评估与确定性业务测试分别记录。测试通过不能替代真实 DeepSeek 对话质量评估；未运行的检查不得标为完成。

## 实施与验证结果

### 已实施的改进

- **连续对话**：按完整 JSON 的序列化大小控制上下文，优先保留当前待补事项、项目和财务状态；保留近期对话，并从超过 80 条的早期用户消息中检索最多三条相关原文，带消息来源。旧草稿不会因召回而恢复成可执行动作。
- **补充与改口**：待补工时期间支持单独更正日期、小时、时薪和精确唯一成员，保留其余字段并重新验证权限；取消、查询和工作描述分开处理。复合或含糊表达仍由模型澄清，不直接写账。
- **项目边界**：新请求从会话恢复项目时重新检查当前成员资格；切项目同时写入历史分界；慢响应在落库前检查项目和分界版本，拒绝 A→B 和 A→B→A 后的过期响应。前端同步口头切换结果，阻止请求期间切换，并隔离过期历史加载。
- **财务确认**：工时、工资和支付通过持久化消息 ID 确认，复用已有账务服务；重复请求返回同一结果；批量支付整体回滚；重新校验当前权限和原项目，浏览器不能替换金额、人员或项目。
- **金额与状态**：支付草稿使用审计后的应付金额，确认时在账务锁内检查该金额；成本、到账、预算、现金和 VC 分开表达。个人可见范围、无权查看、已取消工资、审计归零、归档项目、旧未付工资均有明确语义。
- **权限与评审**：私有报价及分工与原生页面共用过滤；待办分别判断审批和付款权限；团队验收复用指定验收人规则；提案评审加事务锁并要求三名不同评审者；审批草稿绑定原版本。
- **用户操作**：首条快捷工具结果可持久化，刷新后保留财务执行状态；同一天多条草稿独立确认；中文输入法回车不误发送；旧项目的任务/计划/入账卡片不能误作用于新项目；邀请按钮明确为“生成邀请链接”。
- **维护方式**：上下文、财务事实、财务确认和会话并发控制分别提取到独立模块，增加可复用的隔离测试入口和冻结的真实模型评估脚本。
